Quick setup:
===============================================================================

Drop 'Prefabs\AudioStreamNetCodeServer' and 'Prefabs\NetworkManager' into the scene
- you can set the server to automatically start in Host or Server mode, or start the network scene as a Client

If you now run two instances (editor + build, or build + build) with one set to start automatically as Server/Host and the other as Client on the same machine,
the Client should automatically connect to the default localhost IP and you should be hearing the demo audio on the client (the server prefab has monitoring volume set to 0 by default so it's not audible).

Please also refer to the demo scene 'Demo\AudioStreamNetCodeDemo' and the 'AudioStreamNetCodeDemo.cs' script, where everything is set up, and to 'Prefabs\AudioStreamNetCodeServer' to see how components are ordered on a GameObject.

The package asmdef has weak references (non-GUID) to "Unity.Netcode.Runtime" and "AudioStreamSupport".


-------------------------------------------------------------------------------
About Demo:
    The AudioStreamNetCodeServer prefab instance in the demo scene and the AudioStreamNetCodeClient prefab both have an extra graphics child GameObject just for demo purposes.
    These are used by the AudioStreamNetCodeDemo script only and can be removed/replaced/changed.

    - The demo tints the color of the sprite and places the client transform randomly around the origin when it's spawned.
    - All clients also have their transforms synced to the server:
        - The AudioStreamNetCodeClient prefab has NetworkTransform, and the demo adds a script that allows clients to move at runtime
        - use W/A/S/D to move, R to reset the position
        - see the OnClientConnected event handler in AudioStreamNetCodeDemo

    - Use 'Use lower latency mode (2D only receivers)' before starting Host/Server to use all needed/receiving AudioSources in lower latency 2D mode over the network
    See also the 'Lower latency 2D mode' section below

    - if the skybox/background is missing in the scene, please assign the Demo\_Support\Textures\Skybox material to SkyboxMaterial in Lighting Settings <<


-------------------------------------------------------------------------------
General:
    - you will probably want to increase NetworkManager/Transport defaults such as 'Max Send Queue Size' if connecting many clients
    - moreover, since the demo uses Transform syncing for all clients, these use a Reliable queue which requires higher bandwidth ->
        when using audio transfer only, the limits on Transport can be eased


===============================================================================
Server/Source component:
===============================================================================

'AudioStreamNetCodeServer' can be attached to any GameObject which produces sound in a Unity scene - so any AudioSource or AudioListener.
It acts as a Singleton with the DontDestroyOnLoad flag and has a hard dependency on 'AudioSourceCaptureBuffer' which will be automatically added if necessary.

You can attach any effect/s in the chain on the prefab/GameObject above 'AudioSourceCaptureBuffer'.
Audio is encoded after all sound processing is done, so it respects all effects/spatialization enabled on the GameObject.

For each connected client, a separate GameObject is created and parented under 'AudioStreamNetCodeServer' - this is currently necessary because each client requires a unique mix since it can transmit back (see below),
thus requiring a unique AudioSource and encoder.
Client mixes/encoders try to be as efficient as possible, but due to the above there's some CPU processing overhead which scales linearly with the number of connected clients.
[a couple of clients is OK, but this will improve in the future]

On the server, all clients' GameObject names also contain their connection ID.

If it is not set to automatically start as Host/Server/Client, call the appropriate method StartHost() / StartServer(), resp. NetworkManager.Singleton.StartClient() for each mode.

For scripting, please also refer to the demo scene 'Demo\AudioStreamNetCodeDemo' and the 'AudioStreamNetCodeDemo.cs' script.



===============================================================================
NetworkManager:
===============================================================================

A single NetworkManager in the scene is required by Unity NetCode.
The 'NetworkManager' prefab in 'Prefabs' is a version customized for AudioStreamNetCode, also containing NetworkTransport, which has the 'AudioStreamNetCodeClient' prefab set as Player Prefab.
It uses all default settings for NetworkManager and NetworkTransport otherwise.

IMPORTANT: Relay Unity Transport is not implemented due to Unity having a restriction on this type of network data on their service - please see 'Relay and alternative transports' below.



===============================================================================
Client component:
===============================================================================

'AudioStreamNetCodeClient' is a NetworkBehaviour component which decodes incoming network data into its own AudioSource (the AudioSource on the same GameObject).

Optionally, it can also send encoded audio back to the server - either from its own AudioSource or from UnityMicrophone
These are set up on separate GameObjects as children of AudioStreamNetCodeClient and their audio is transmitted when 'transmitClientAudioSource'/'transmitClientMicrophone' are ON.

    'ClientTxAudioSource' - client audio, customize the AudioSource here
    'ClientTxUnityMicrophone' - client microphone, please customize the AudioStreamUnityMicrophone settings, such as Microphone Device Id, here

As per the above, this compressed stream is decoded on the server and mixed with audio from the server and all other clients.

The 'AudioStreamNetCodeClient' prefab in 'Prefabs' is set up like this and is set as Player Prefab on the NetworkManager.


===============================================================================
Relay and alternative transports:
===============================================================================

Relay Unity Transport is not implemented so far, mainly due to a UT service restriction.

See e.g. https://docs.unity.com/relay/introduction.html#Fair_usage:
"
The Relay service is intended for the transmission of multiplayer game state only. Usage of the service outside this category is subject to rate limiting or termination under terms of service.
Unfair use of the Relay service includes, but is not limited to, the following examples:
Audio streaming of any nature, including voice chat
Video streaming of any nature
File transfer services
Distributed computation unrelated to gameplay, including crypto mining
General network proxying and other VPN-like services
"


It is possible, however, to use a custom transport & relay for NetworkManager - see https://docs-multiplayer.unity3d.com/netcode/current/advanced-topics/transports#community-transports-or-writing-your-own
and https://github.com/Unity-Technologies/multiplayer-community-contributions


No direct Relay support for any of the custom transports has been implemented so far.


===============================================================================
Audio encoder/decoder:
===============================================================================

For audio de/compression, the Opus codec C# implementation is used - [https://github.com/lostromb/concentus] - via a pair of components: AudioStreamEncoder and AudioStreamDecoder

The AudioStreamEncoder component's public fields should be reasonably well explained via tooltips on each field in the Editor.

Both have a 'Monitoring Volume' slider which doesn't modify the processed signal, but allows it to be monitored after it enters/leaves the de/encoder.


===============================================================================
Lower latency 2D mode:
===============================================================================

To improve audio latency over the network, the host/server ('AudioStreamNetCodeServer' component/prefab) can use the 'use2DRecevingAudioSources' option/toggle -
- when ON, all receiving AudioSources play in 2D mode (with ~ignored spatialization)
- receiving AudioSources are: all receiving clients, and all clients' audio received on the server when clients are transmitting back (which in turn gets mixed for all other clients)
- note that this means that the original signal/audio _can_ still be spatialized - this spatialized signal is then sent over the network but receivers play it identically ~regardless of their position in 3D
you can, of course, still use 'Spatial Blend' on clients' prefabs as usual

This can lead to interesting combinations - I recommend running at least two separate demo client instances connecting to a host/server to see it in action.



===============================================================================
IL2CPP builds and building with IL2CPP runtime checks turned off:
===============================================================================

Code running the tightest audio loops can be optionally built with null, array bounds and division by zero checks turned off for IL2CPP builds (which is generally recommended but it's advisable to verify that the build is running correctly with them being turned off first)

The needed attributes for this are included in the package, but you are advised to verify this, i.e. check for your Unity version, see e.g. https://docs.unity3d.com/2018.4/Documentation/Manual/IL2CPP-CompilerOptions.html (and your/respective Editor version) how to do that.
The file 'Il2CppSetOptionAttribute.cs' must be placed into the project's 'AudioStream/Support' folder (or any of its subfolders) - it must be part of the 'AudioStreamSupport' assembly definition

- if the project doesn't already have the ENABLE_IL2CPP compiler define added, add ENABLE_IL2CPP to Scripting Define Symbols in Player Settings
